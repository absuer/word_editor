# 01_封面

欢迎来到本次技术分享。今天我们要介绍的是一个基于 RAG 架构的智能客服系统，它整合了 Streamlit 前端、LangChain LangGraph 代理框架和 ChromaDB 向量数据库，形成了一套完整的智能问答解决方案。

---

# 02_目录

接下来的分享将分为七个部分：我们首先了解项目整体定位，然后深入技术栈和架构设计，接着拆解数据处理流程和四大核心模块，最后总结核心特性并演示如何快速部署运行。

---

# 03_项目概述

这个系统的核心思路是将用户上传的文档转化为可检索的知识库。当用户提问时，系统优先从文档中语义检索答案，只有在文档覆盖不足时才自动回退到网络搜索。它支持七种常见的文件格式，包括 PDF、Word、Markdown 和图片 OCR，基本覆盖了企业日常的文档类型。同时内置的多轮对话记忆机制确保每次回答都理解前文语境。

---

# 04_技术栈一览

系统基于三大核心技术构建。展示层使用 Streamlit，以纯 Python 代码实现 Web 界面和会话管理。代理层基于 LangChain 和 LangGraph，通过 ReAct 模式编排多个工具调用。存储层使用 ChromaDB 作为向量数据库，配合 HuggingFace 的多语言嵌入模型在本地 CPU 上运行。大语言模型选择了 DeepSeek，通过 OpenAI 兼容接口接入，网络搜索回退使用 DuckDuckGo，无需额外 API 密钥。

---

# 05_系统架构总览

系统采用经典的三层水平架构。最上层是展示层，包含 Streamlit 界面、会话状态和设置面板。中间是代理层，LangGraph ReAct Agent 负责编排两个工具：retriever 用于文档语义检索，web_search 用于网络搜索回退。最下层是存储层，包含 ChromaDB 向量库、HuggingFace 嵌入模型和文件加载器。基础设施层提供配置管理、日志记录和测试支持。

---

# 06_数据处理流程

数据经过四个阶段完成从文件到智能回答的流转。第一阶段是文件上传，用户在 Web 界面拖拽或点击上传，系统基于文件名和大小进行去重校验。第二阶段是解析分块，系统自动检测文件格式并调度对应的加载器，使用中文感知的分割策略将文档切分为语义连贯的分块。第三阶段是向量化存储，每个分块通过嵌入模型转为向量并存入 ChromaDB。第四阶段是检索生成，用户提问后 retriever 先检索文档，不足时回退到 web_search，最后 DeepSeek 大模型流式生成回答并标注来源。

---

# 07_文件加载器

FileLoader 模块提供了七种格式的自动检测与解析能力。每种格式都有对应的 LangChain 加载器，图片则通过 pytesseract 进行中英文混合 OCR 识别。分块策略采用 RecursiveCharacterTextSplitter，特别配置了中文句号作为核心分隔符，chunk 大小为一千字符，重叠一百五十字符。每个分块都会注入完整的元数据，包括原始文件名、格式类型、分块序号和上传时间，为后续的回答溯源提供基础。

---

# 08_向量存储与代理

VectorStoreManager 封装了 ChromaDB 和 HuggingFace 嵌入模型。采用懒加载初始化策略，只有首次访问时才创建 Chroma 客户端，同时内置了基于来源和序号的分块去重逻辑。AgentManager 使用 LangGraph 的 create_react_agent 创建 ReAct 代理，配置了 retriever 和 web_search 两个工具。retriever 优先调用，返回带来源标注的文档内容；web_search 作为回退方案，通过 DuckDuckGo 的 html 和 lite 双后端保证可用性。流式输出基于 LangGraph 的 values 模式，每次 AI 消息更新时 yield 完整响应文本。

---

# 09_记忆管理

MemoryManager 封装了 ConversationBufferWindowMemory，默认保留最近四轮对话。当用户提问时，系统先加载对话历史，将其注入 Agent 的 prompt 中，模型生成回答后再将本轮对话保存到记忆中。滑动窗口机制确保上下文不会无限增长，避免推理速度下降和 Token 浪费。记忆存储在 Streamlit 的 session_state 中，页面刷新后依然保持。

---

# 10_核心特性与亮点

总结起来，这个系统有六大核心优势。多格式支持覆盖了七种常见文件类型。中文深度优化体现在分块策略和多语言嵌入模型上。智能回退机制确保文档不足时无缝切换到网络搜索。流式响应提供了实时逐字输出的体验。去重与持久化保证了数据一致性和跨会话可用性。回答可溯源让每个答案都附带文件名和页码，增强可信度。

---

# 11_运行与部署

部署这个系统非常简便。首先通过 pip 安装依赖，然后配置环境变量文件，设置 API 密钥、基础 URL 和模型名称，最后一条 streamlit run 命令即可启动应用。运行测试只需执行 pytest，测试套件覆盖了从文件加载到向量检索到代理创建的完整流程。所有数据包括向量库、上传文件和日志都持久化在 data 目录下。

# 12_总结

让我们快速回顾今天的内容。智能客服系统将 RAG 架构、LangGraph Agent 编排和 ChromaDB 向量检索深度整合，提供了一个轻量高效、即装即用的智能问答平台。它支持七种文档格式、中文优化分块、本地嵌入、双工具智能回退，并且全流程可溯源，非常适合企业内部知识库问答场景。感谢各位的时间，欢迎提问。
